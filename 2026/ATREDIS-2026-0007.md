# GStreamer - Divide by Zero in qtdemux_parse_trak and qtdemux_audio_caps

## Vendors

* GStreamer

## Affected Products

GStreamer gst-plugins-good < 1.28.2

## Summary

When parsing MP4 audio tracks, the `isomp4` plugin's `qtdemux_parse_trak` and `qtdemux_audio_caps` functions do not sufficiently validate atom data before performing division operations, causing the process to crash due to integer division by zero.

## Remediation/Mitigation

This issue was patched in the gst-plugins-good 1.28.2 release. A [patch file](https://gitlab.freedesktop.org/gstreamer/gstreamer/-/merge_requests/11243.patch) is also available for older releases.

## Technical Details

When parsing the `fpcm` atom, `qtdemux_parse_trak` does not validate that the sound sample description's `entry->n_channels` field is non-zero before using it as a divisor to calculate the number of bytes per sample.

`subprojects/gst-plugins-good/gst/isomp4/qtdemux.c` (`qtdemux_parse_trak`):

```c
  // ...
  case FOURCC_fpcm:
    /* Sometimes these are set to 0 in the sound sample descriptions so
      * let's try to infer useful values from the other information we
      * have available */
    if (entry->bytes_per_sample == 0)
      entry->bytes_per_sample =
          entry->bytes_per_frame / entry->n_channels;
  // ...
```

Similarly, when parsing the `lpcm` atom, `qtdemux_audio_caps` does not validate that `entry->n_channels` is non-zero before using it as a divisor to calculate the sample width.

`subprojects/gst-plugins-good/gst/isomp4/qtdemux.c`  (`qtdemux_audio_caps`):

```c
  // ...
  case FOURCC_lpcm:
  {
    // ...
    if (stsd_version == 0 && version == 0x00020000 && len >= 16 + 56) {
      /* sample description entry (16) + sound sample description v0 (20) */
      depth = QT_UINT32 (data + 36 + 20);
      flags = QT_UINT32 (data + 36 + 24);
      width = QT_UINT32 (data + 36 + 28) * 8 / entry->n_channels;
    }
    // ...
```

As a result, when `n_channels` is set to 0, integer division by zero occurs and the program crashes due to a floating-point exception (SIGFPE).
