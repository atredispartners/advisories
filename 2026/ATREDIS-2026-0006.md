# GStreamer - Global Buffer Overflow in qtdemux_parse_chnl via defined_layout Field

## Vendors

* GStreamer

## Affected Products

GStreamer gst-plugins-good < 1.28.2

## Summary

While parsing an MP4 file, the `isomp4` plugin's `qtdemux_parse_chnl` function may read past the end of a global array, potentially leading to information disclosure.

## Remediation/Mitigation

This issue was patched in the gst-plugins-good 1.28.2 release. A [patch file](https://gitlab.freedesktop.org/gstreamer/gstreamer/-/merge_requests/11243.patch) is also available for older releases.

## Technical Details

When parsing the `chnl` sub-box of the audio sample entry (`stsd`) box, the `qtdemux_parse_chnl` function does not validate the `defined_layout` field before using it to index into the `chnl_layouts` global array. As a result, a global buffer overread occurs when `defined_layout` is greater than or equal to the size of the array (14).

`src/gstreamer/subprojects/gst-plugins-good/gst/isomp4/qtdemux.c`:

```c
if (!gst_byte_reader_get_uint8 (br, &defined_layout)) {
        GST_WARNING_OBJECT (qtdemux, "Too short chnl box");
        goto error;
      }
      // ...
      // Overread occurs here:
        const GstAudioChannelPosition *layout = chnl_layouts[defined_layout];
        // ...
```

`qtdemux_parse_chnl` subsequently indexes into the `layout` pointer to copy data from the specified layout structure into the `positions` array, which is used to derive a channel mask that may be accessible to attackers in the program's output.

However, there does not appear to be a straightforward path for an attacker to reliably recover the contents of `positions` from the channel mask, as mask derivation is lossy and several validation checks before, during, and after derivation cause `qtdemux_parse_chnl` to bail out early when there is unexpected data in `positions` or `layout`. As a result, this issue may not be exploitable.

        positions[c] = layout[l_c];
        break;

      l_c += 1;
